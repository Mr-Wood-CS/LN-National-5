# Query Design

A query design records what information is needed and which records to include. Before writing SQL, identify the tables, output fields, search criteria and sort order.

## Worked example

Using the [Bakery and Product tables](../../4.4-implementation/bakery-database.md), list the product name, price in pence and bakery name for Glasgow products costing under £2. Put the cheapest products first. Sort products with the same price by name.

| Design element | Decision |
| --- | --- |
| Tables | `Product`, `Bakery`, linked by `BakeryID` |
| Fields to display | `ProductName`, `PricePence`, `BakeryName` |
| Search criteria | `Town = 'Glasgow'` AND `PricePence < 200` |
| Sort order | `PricePence` ascending, then `ProductName` ascending |

The town is needed to decide which records qualify. The output only needs the three requested fields. A product priced exactly £2 is excluded because the requirement says **under £2**. The exam design table can express the intended result before the query is translated into SQL.
